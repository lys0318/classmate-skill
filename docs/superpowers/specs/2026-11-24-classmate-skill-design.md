# classmate 스킬 설계

- 작성일: 2026-11-24
- 상태: 승인됨 (2026-11-24)
- 표시: *(제안)* = 대화에서 사용자가 직접 정하지 않고 설계자가 정한 것. 사용자가 바꿀 수 있다.

## 1. 왜 만드나

AI로 바이브코딩하는 사람이 늘면서, 에이전트 제안을 읽지 않고 수락만 누르는 경우가 많아졌다. 결과물은 생기지만 본인은 자기 프로젝트의 구조, 코드, 데이터 흐름, 그렇게 설계한 이유, 문제를 해결한 과정을 설명하지 못한다.

classmate는 작업 중간중간 에이전트가 방금 한 일을 설명하고 퀴즈로 이해도를 확인한다. 프로젝트가 끝날 때는 전체 구조를 복습시키고 종합 퀴즈와 이해도 리포트를 준다. 목표는 사용자가 **자기 프로젝트를 남에게 설명할 수 있게 되는 것**이다.

## 2. 대상

Claude Code나 Codex로 작업을 많이 하는 바이브코더. 터미널(또는 IDE/데스크톱 앱)에서 에이전트와 대화하며 개발한다.

## 3. 목표 / 비목표 / 안티목표

**목표**
- 기능 하나가 완성될 때마다 짧은 설명과 퀴즈를 제공한다.
- 프로젝트 마무리 때 전체 구조 설명, 종합 퀴즈, 이해도 리포트(HTML)를 제공한다.
- 난이도를 3단계로 조절할 수 있다.
- 폴더 복사만으로 설치되고, Claude Code와 Codex 양쪽에서 동작한다.

**비목표 (이번 버전에서 하지 않음)**
- 웹 서비스, 로그인, 서버
- 과목을 만들고 자료를 올려 학습하는 확장판(NotebookLM식). 별도 프로젝트로 나중에 한다.
- 브라우저에서 퀴즈 풀기 (아래 방식 ③)
- hook을 이용한 자동 실행
- 점수 경쟁, 배지 같은 게임 요소. 팀·여러 사용자 기능

**안티목표 (동작하더라도 이렇게 되면 실패)**
- 너무 자주 끼어들어서 사용자가 꺼버린다. 예: 오타 수정이나 설정 변경에도 퀴즈가 뜬다.
- 퀴즈가 변수 이름 외우기 같은 암기 문제라서 이해도를 재지 못한다.
- 설명이 길어서 아무도 읽지 않는다.
- 퀴즈가 작업을 막는다. 항상 '나중에'를 고를 수 있어야 한다.
- 퀴즈를 진행하는 동안 에이전트가 코드를 고친다.
- 사용자가 모르는 사이에 학습 기록이나 classmate 지시문이 사용자의 저장소에 커밋된다.

## 4. 제약

- **스킬 형식:** `SKILL.md`(frontmatter에 `name`, `description` 필수)와 선택적 하위 폴더로 이루어진 디렉터리. Claude Code와 Codex가 같은 형식을 읽는다.
  - Claude Code: `~/.claude/skills/classmate/`(개인) 또는 `<프로젝트>/.claude/skills/classmate/`. 호출은 `/classmate <인자>`.
  - Codex: `~/.agents/skills/classmate/`(개인) 또는 `<프로젝트>/.agents/skills/classmate/`. 호출은 `$classmate <인자>` 또는 `/skills`.
- **런타임 의존성 없음:** Node나 Python 설치를 요구하지 않는다. 실행 스크립트 없이 에이전트가 파일을 직접 읽고 쓴다.
- **토큰 비용은 사용자 구독에서 나간다.** 설명과 퀴즈는 짧게 유지하고, 세부 규칙은 필요할 때만 읽도록 나눠 둔다.
- Windows, macOS, Linux에서 동작해야 한다.
- 리포트의 구조도는 Mermaid(CDN)로 그린다. 오프라인이면 그림 대신 원문 텍스트가 보이는 것을 허용한다.

## 5. 방식 (검토한 것과 선택)

| 방식 | 내용 | 장점 | 단점 |
|---|---|---|---|
| ① 대화창 전용 | 설명·퀴즈·복습을 모두 대화창에서 처리 | 설치가 폴더 복사뿐이고 Codex에서도 거의 그대로 동작 | 마지막 복습에서 구조도나 이해도 그래프를 보여주기 어려움 |
| **② 대화창 퀴즈 + HTML 리포트 (선택)** | ①에 더해 `review` 때 `report.html` 파일 하나를 만들어 브라우저로 염. 서버 없음 | 작업 중엔 흐름이 안 끊기고, 복습은 눈으로 볼 수 있음. 추가 설치 없음 | 리포트는 보기 전용. 다시 풀기는 대화창에서 해야 기록됨 |
| ③ 브라우저 대시보드 | 로컬 서버를 띄워 기능마다 브라우저에 퀴즈 화면 표시 | 가장 앱 같은 경험 | 터미널과 브라우저를 오가며 흐름이 끊김. 서버 관리 필요, 구현량 최대, Codex 지원 어려움 |

**②를 고른 이유:** 기능별 퀴즈는 바이브코더가 이미 보고 있는 대화창 안에서 끝나야 덜 귀찮다. 반면 프로젝트 전체 복습은 그림으로 볼 때 효과가 크다. ①이 ②의 부분집합이므로 ①에 해당하는 부분을 먼저 만들어 써보고 리포트를 얹는다.

**함께 뺀 것:** 웹 서비스(대상이 터미널 사용자라 불필요), hook 자동 실행(응답마다 돌아 낭비가 크고 Codex와 방식이 다름).

## 6. 사용자 경험

### 6.1 명령

| Claude Code | Codex | 하는 일 |
|---|---|---|
| `/classmate on` | `$classmate on` | 이 프로젝트에서 켜기 |
| `/classmate off` | `$classmate off` | 끄기. 학습 기록은 남긴다 |
| `/classmate` | `$classmate` | 지금 바로 최근 작업을 설명하고 퀴즈. 미룬 퀴즈가 있으면 먼저 제안 |
| `/classmate level 입문\|중급\|고급` | `$classmate level …` | 난이도 변경 |
| `/classmate review` | `$classmate review` | 프로젝트 복습, 종합 퀴즈, 리포트 생성 |

### 6.2 켜기와 끄기

GitHub에 공개해 여러 사람이 쓰는 스킬이므로, 사용자의 프로젝트 저장소에는 커밋될 흔적을 남기지 않는다.

`on`을 실행하면:
1. **처음 한 번만:** 에이전트가 세션마다 자동으로 읽는 개인 전역 지침 파일에 표시된 블록을 넣는다. 넣기 전에 넣을 내용과 파일 위치를 보여주고 동의를 받는다. 파일이 없으면 만든다.
   - Claude Code: `~/.claude/CLAUDE.md`
   - Codex: `~/.codex/AGENTS.md`
   ```
   <!-- classmate:start -->
   현재 프로젝트에 `.classmate/config.json`이 있고 enabled가 true이면,
   기능 하나를 완성했을 때 classmate 스킬을 실행해 설명과 이해도 퀴즈를 제공한다.
   <!-- classmate:end -->
   ```
   이유: 스킬 설명만으로는 에이전트가 작업 도중 스킬을 떠올리지 못할 수 있다. 전역 지침 파일은 매 세션 읽히므로 hook 없이도 안정적으로 동작하고, 조건을 걸어 두었으므로 classmate를 켠 프로젝트에서만 동작한다.
2. 난이도를 묻는다. 기본값은 중급이다. *(제안)*
3. 프로젝트에 `.classmate/`를 만들고 `config.json`에 `enabled: true`와 난이도를 저장한다.
4. `.classmate/` 안에 내용이 `*` 한 줄인 `.gitignore`를 둔다. 폴더가 스스로 git에서 빠지므로 사용자의 `.gitignore`는 건드리지 않는다. 기록을 커밋하고 싶은 사용자는 이 파일만 지우면 된다. *(제안)*

`off`를 실행하면 `config.json`의 `enabled`를 false로 바꾼다. 학습 기록과 전역 블록은 그대로 둔다.

**완전히 지우려면** (README에 안내): 전역 지침 파일에서 `classmate:start`부터 `classmate:end`까지의 블록을 지우고 스킬 폴더를 삭제한다. 블록만 남아 있어도 `.classmate/`가 없는 프로젝트에서는 아무 일도 하지 않는다.

### 6.3 기능이 완성되었을 때

**완성 판단 (에이전트가 판단)** *(제안)*
- **해당:** 사용자가 쓸 수 있는 기능 하나(화면, API, 명령 등)가 구현되고 동작 확인까지 끝났을 때
- **제외:** 오타·스타일·설정·의존성 변경, 기능의 중간 단계, 아직 실패하는 상태
- **애매하면 끼어들지 않는다.** 과한 개입이 가장 큰 실패 요인이다.
- 사용자가 `/classmate`로 직접 부르면 판단 없이 바로 진행한다.

**끼어드는 시점** *(제안)*
- 에이전트가 사용자에게 차례를 넘길 때만 끼어든다. 여러 단계 계획을 자동으로 진행하는 도중에는 멈추지 않는다.
- 한 번에 기능이 여러 개 완성되면 묶어서 한 번만 묻는다. 설명은 기능별로 짧게 쓰고, 퀴즈는 모두 합쳐 3~5문제로 낸다. 학습 노트는 기능마다 따로 남긴다.

**'최근 작업'의 범위** *(제안)*
- `/classmate`로 부르면 마지막 학습 노트 이후의 작업을 다룬다.
- 이번 대화에 작업 내용이 있으면 그것을 쓴다. 없으면(새 세션 등) 마지막 노트 이후의 git 커밋과 변경 내역으로 파악한다. 둘 다 없으면 무엇을 다룰지 사용자에게 묻는다.
- 기록이나 대화에 없는 설계 이유와 문제 해결 과정은 지어내지 않는다. 그럴 때는 코드에서 확인할 수 있는 영역(구조, 코드, 데이터 흐름)만 묻는다.

**흐름**
1. **짧은 설명** (10줄 안팎): 바뀐 파일, 데이터 흐름(화살표 한 줄), 이 방식을 고른 이유와 고려한 대안, 막혔던 문제와 해결 과정. 설명 깊이는 난이도를 따른다.
2. **퀴즈 여부를 묻는다:** [지금] [나중에]
3. **지금을 고르면 퀴즈 3문제:** 객관식 2개와 서술형 1개. *(제안)*
   - 각 문제는 다섯 영역 중 하나로 태그한다: **구조, 코드, 데이터 흐름, 설계 이유, 문제 해결**. 사용자가 처음에 말한 "설명하지 못하는 것들"을 그대로 영역으로 삼은 것이다.
   - Claude Code에서는 객관식을 선택지 UI(`AskUserQuestion`)로 한 번에 묻고, 서술형은 대화로 받는다. *(제안)*
   - 선택지 UI가 없는 환경(Codex 등)에서는 번호를 입력해 답한다.
4. **채점과 해설:** 서술형은 맞음/부분/틀림으로 채점한다. 틀린 문제는 정답, 이유, 관련 코드 위치(파일:줄)를 알려준다.
5. **기록 저장** (6.5 참고)

**나중에를 고르면** 설명과 퀴즈 문제를 '미룸' 상태로 저장한다. 다음 `/classmate`와 `review` 때 다시 꺼낸다.

**퀴즈 문제 원칙**
- 이 프로젝트의 실제 코드와 이번 작업에 근거한다. 일반 상식 문제는 내지 않는다.
- 이름 외우기 같은 암기 문제는 내지 않는다.
- "왜", "어디로", "만약 ~라면" 형태를 중심으로 낸다.
- 퀴즈를 진행하는 동안 코드는 고치지 않는다.

### 6.4 난이도

| 단계 | 설명과 퀴즈가 다루는 것 |
|---|---|
| 입문 | 무엇을 만들었는지, 용어의 뜻, 각 파일의 역할 |
| 중급 | 왜 이렇게 짰는지, 데이터가 어디서 어디로 가는지 |
| 고급 | 다른 방식과의 비교, 예외 상황, 고장 났을 때 어디부터 볼지 |

### 6.5 학습 기록 (`.classmate/`)

```
.classmate/
├─ .gitignore           # 내용은 `*` 한 줄. 폴더 전체를 커밋에서 제외
├─ config.json          # enabled, 난이도
├─ features/
│  └─ 001-로그인.md      # 기능별 학습 노트 (완성 순서대로 번호)
├─ reviews/             # review 때 낸 종합 퀴즈 기록
├─ report.html          # review 때 리포트 틀을 그대로 복사
└─ report-data.js       # review 때 생성하는 리포트 데이터
```

기능별 학습 노트는 사람이 다시 읽을 수 있는 복습 자료이면서 `review`의 재료다. 담을 내용은 다음과 같다.
- 날짜, 기능 이름, 상태(완료/미룸)
- 설명 (6.3의 1번 내용)
- 퀴즈 문제마다: 문제, 영역, 정답, 사용자 답, 결과, 해설

정확한 형식은 구현자가 정한다. 단, 에이전트가 읽고 쓰기 쉬우면서 사람이 그대로 읽을 수 있어야 한다.

### 6.6 프로젝트 마무리 (`review`)

1. **전체 구조 설명:** 주요 폴더와 파일의 역할, 핵심 데이터 흐름 1~3개, 그동안의 설계 결정 모음. 학습 노트와 현재 코드를 근거로 한다. 노트가 없는 기능의 설계 이유는 지어내지 않고 '기록 없음'으로 표시한다.
2. **종합 퀴즈 5~10문제:** 틀렸던 개념, 미룬 퀴즈, 전체 구조에 관한 문제를 중심으로 낸다.
3. **리포트 생성:** `.classmate/report.html`을 만들고 브라우저로 연다.

리포트 구성:
- 프로젝트 한 줄 요약
- 구조도 (Mermaid)
- 기능별 학습 타임라인
- 다섯 영역별 이해도 (누적 정답률) *(제안)*
- 틀린 문제와 해설
- 다음에 공부할 것

`review`는 프로젝트 도중에도 몇 번이든 실행할 수 있다(중간 점검).

**리포트 만드는 방법** *(제안)*: 디자인과 그리는 코드를 담은 `assets/report-template.html`을 스킬에 넣어 두고, 에이전트는 틀을 그대로 `.classmate/report.html`로 복사하고 데이터만 `.classmate/report-data.js`에 쓴다. 매번 HTML을 새로 쓰면 토큰이 낭비되고 모양도 매번 달라지기 때문이다. 데이터를 별도 파일로 두는 이유는 퀴즈에 `</script>` 같은 코드가 섞여도 HTML이 깨지지 않게 하기 위해서다.

## 7. 저장소와 스킬 폴더 구성 *(제안)*

```
classmate-skill/                  # 이 저장소
├─ README.md                      # 소개, 설치법(Claude Code / Codex), 사용법
└─ skills/
   └─ classmate/                  # 사용자가 복사해 가는 폴더
      ├─ SKILL.md                 # 진입점: 명령 분기, 기능 완성 흐름 요약
      ├─ references/
      │  ├─ explain-and-quiz.md   # 설명 형식, 문제 유형, 난이도 기준, 채점 규칙
      │  └─ review.md             # 복습 흐름, 리포트 데이터 형식
      └─ assets/
         └─ report-template.html  # 리포트 틀
```

- `SKILL.md`는 짧게 유지하고, 세부 규칙은 `references/`에 두어 필요할 때만 읽게 한다.
- `skills/classmate/` 구조는 나중에 Claude Code 플러그인으로 묶을 때 그대로 쓸 수 있다.
- 스킬 지시문은 한국어로 쓴다(만든 사람이 읽고 고치기 쉽게). 에이전트의 출력 언어는 사용자가 대화하는 언어를 따른다.

## 8. 구현 순서와 배포

**구현 순서** *(제안)*
1. 1단계: 켜기/끄기, 기능 완성 시 설명과 퀴즈, 미루기, 난이도, 학습 노트 (방식 ①에 해당)
2. 점검: 사용자가 실제 프로젝트에서 써보고 귀찮은 점, 퀴즈 품질을 확인한다. 사용자가 원하면 건너뛰고 바로 진행한다.
3. 2단계: `review`와 HTML 리포트

**배포**
- v1: GitHub 저장소와 README의 설치법(폴더 복사)
- 나중에: Claude Code 플러그인 마켓플레이스 등록. 이때는 전역 지침 파일을 건드리는 대신 세션 시작 hook으로 지시를 넣는 방법을 검토한다.
