# 프로젝트 복습 (review)

SKILL.md의 공통 규칙과 난이도 표를 함께 따른다. 이 흐름 동안 프로젝트 코드는 고치지 않는다. 프로젝트 도중에도 몇 번이든 실행할 수 있다(중간 점검).

`.classmate/config.json`이 없으면 먼저 `on`으로 켜라고 알리고 끝낸다. `enabled`가 `false`여도 사용자가 직접 불렀으므로 진행한다.

## 1. 자료 모으기

- `.classmate/features/*.md`(학습 노트)와 `.classmate/reviews/*.md`(지난 복습)를 모두 읽는다. 형식은 `references/explain-and-quiz.md` 5절에 있다.
- `.classmate/learn.md`가 있으면 그 지도(무엇·실행·구조)와 장 목록을 2절 구조 설명에 재사용하고, 코드는 필요한 만큼만 더 읽는다.
- 그렇지 않으면 프로젝트의 현재 코드에서 주요 폴더와 파일, 진입점을 훑는다.
- 학습 노트가 하나도 없으면 코드만으로 진행한다. 설계 이유와 문제 해결 과정은 지어내지 않고 `기록 없음`으로 다룬다.

## 2. 전체 구조 설명 (퀴즈보다 먼저)

한 번에 보여준다. 깊이는 config의 난이도를 따른다.

- **주요 폴더와 파일의 역할:** 5~10줄
- **핵심 데이터 흐름:** 1~3개, 화살표 한 줄씩
- **설계 결정 모음:** 학습 노트의 `이유`를 기능별로 모은다. 이유가 없거나 `기록 없음`인 기능은 지어내지 않고 `기록 없음`으로 쓴다. `(추정, 출처: …)`·`(본인 기억)` 표시는 지우지 말고 그대로 옮긴다. 추정을 사실처럼 말하지 않는다.
- **그동안 틀렸던 개념:** 있으면 한두 줄로

## 3. 종합 퀴즈 (5~10문제)

사용자가 직접 불렀으므로 지금/나중에를 묻지 않는다. 시작하기 전에 문제 수만 알린다. 도중에 그만두자고 하면 남은 문제는 답하지 않은 상태로 저장한다.

문제는 아래 순서로 채운다. 모두 합쳐 5~10문제.

1. **미룬 퀴즈:** `status: deferred` 노트의 `결과: 미응답` 문제를 그대로 다시 낸다.
2. **기록만 된 기능:** `status: noted` 노트마다 1~2문제. 노트의 설명과 현재 코드에 근거하고, 노트의 이유가 `기록 없음`이면 `설계 이유` 문제는 내지 않는다.
3. **틀렸던 개념:** `틀림`·`부분`이었던 문제의 개념을 다른 형태로 다시 묻는다. 같은 문제를 그대로 내지 않는다.
4. **전체 구조:** 파일 사이의 관계, 기능을 가로지르는 데이터 흐름.

- 3·4번 문제는 2개 이상이다. 그래서 1·2번은 합쳐 8개까지만 담는다.
- 1·2번이 8개를 넘으면 오래된 노트부터 담고, 남은 미룬 퀴즈와 기록만 된 기능 수를 알린다. 남은 것은 다음 review나 `/classmate`에서 이어진다.
- 객관식과 서술형을 섞는다. 서술형은 1~3개.
- 영역, 출제 원칙, 묻는 방법, 채점과 해설은 `references/explain-and-quiz.md` 4절을 따른다.
- 이유가 `(추정, …)`인 기능으로 `설계 이유` 문제를 낼 때는 정답이 추정이라는 것을 문제나 해설에 밝힌다(예: `해설: 추정이다(출처: README). …`).
- 마지막에 맞힌 개수를 한 줄로 알린다.

## 4. 기록

- **미룬 문제(1번):** 원래 노트의 `내 답:`, `결과:`를 채운다. 노트의 문제를 모두 답했으면 `status: done`으로 바꾼다.
- **기록만 된 기능(2번):** 문제를 그 노트에 `## 퀴즈` 절로 쓰고 `status: deferred`(모두 `미응답`)로 바꾼 뒤 묻는다. 답을 채우고, 모두 답했으면 `status: done`으로 바꾼다. `reviews/`에는 쓰지 않는다.
- **새 문제(3·4번):** `.classmate/reviews/YYYY-MM-DD.md`에 쓴다. 오늘 날짜 파일이 이미 있으면 `-2`, `-3`을 붙인다. `reviews/` 폴더가 없으면 만든다.

```markdown
---
type: review
date: 2026-11-25
---
## 퀴즈
### Q1 [구조] 객관식
문제: …
보기: ① … ② … ③ … ④ …
정답: ②
내 답: ①
결과: 틀림
해설: … (파일:줄)
```

문제 형식은 학습 노트의 `## 퀴즈`와 같다(헤더, `보기:`는 객관식만, `결과:` 값).

## 5. 리포트

1. **틀 복사:** 이 스킬 폴더의 `assets/report-template.html`을 내용 그대로 `.classmate/report.html`로 복사한다(있으면 덮어쓴다). 틀은 고치지 않는다.
2. **데이터 쓰기:** `.classmate/report-data.js`를 아래 형식으로 쓴다(있으면 덮어쓴다). JSON 문법을 지키는 할당문 하나다.
   - 문자열은 JSON 규칙대로 쓴다: 백슬래시는 `\\`, 큰따옴표는 `\"`, 줄바꿈은 `\n`. 코드나 Windows 경로에 든 백슬래시도 모두 `\\`로 쓴다. 예: 노트의 `split('\n')`은 `split('\\n')`, `C:\temp`는 `C:\\temp`. 하나라도 빠지면 글자가 바뀌거나 리포트 전체가 열리지 않는다.
   - 파일 쓰기 도구로 쓴다. 셸의 `echo`·heredoc은 백슬래시를 바꿀 수 있다.

```js
window.CLASSMATE_DATA = {
  "project": "프로젝트 이름",
  "summary": "프로젝트 한 줄 요약",
  "generatedAt": "2026-11-25",
  "level": "중급",
  "structure": {
    "mermaid": "graph TD\n  A[index.html] --> B[app.js]",
    "text": "index.html: 화면 뼈대\napp.js: 동작"
  },
  "flows": ["입력창 → update() → todos 배열 → render()"],
  "decisions": [{ "feature": "할 일 추가", "why": "순서 유지가 쉬운 배열을 택했다" }],
  "features": [
    { "id": "001", "name": "할 일 추가", "date": "2026-11-24", "status": "done", "questions": [
      { "area": "데이터 흐름", "type": "객관식", "question": "…", "answer": "② todos 배열", "userAnswer": "③ 서버", "result": "틀림", "explanation": "…" }
    ] }
  ],
  "reviews": [{ "date": "2026-11-25", "questions": [] }],
  "nextSteps": ["이벤트 위임 다시 보기"]
};
```

채우는 규칙:

| 필드 | 채우는 법 |
|---|---|
| `features` | 학습 노트마다 하나. `id`·`date`·`status`는 frontmatter 그대로, `name`은 `feature` 값. 갱신한 뒤의 노트 기준. 아직 `noted`인 노트는 `"questions": []` |
| `questions` | 노트의 문제마다 하나. 헤더의 영역·유형을 `area`·`type`에, `문제`→`question`, `정답`→`answer`, `내 답`→`userAnswer`(비었으면 `""`), `결과`→`result`, `해설`→`explanation`(없으면 `""`). 객관식의 `answer`·`userAnswer`는 번호 뒤에 노트의 `보기`에서 그 번호의 글을 붙인다(예: `② todos 배열`). 보기 전체 목록은 넣지 않는다 |
| `reviews` | `reviews/*.md` 파일마다 하나(이번 것 포함). `date`는 frontmatter 값 |
| `decisions` | 노트마다 `{ "feature": 기능 이름, "why": 노트의 이유 }`. 이유가 없거나 `기록 없음`이면 `"기록 없음"` |
| `structure.mermaid` | 2절 구조를 Mermaid `graph TD`로. 노드 10개 이내, 노드 이름에 따옴표·괄호·꺾쇠를 쓰지 않는다 |
| `structure.text` | 같은 구조를 글로. 그림을 못 그릴 때 대신 보인다 |
| `flows` | 2절의 핵심 데이터 흐름 |
| `nextSteps` | 틀린 개념과 `기록 없음`이 많은 영역을 바탕으로 2~4개 |

3. **열기:** 운영체제에 맞는 명령으로 `.classmate/report.html`의 절대 경로를 기본 브라우저에서 연다. Windows PowerShell은 `Start-Process "<경로>"`, Git Bash는 `start "" "<경로>"`, macOS는 `open "<경로>"`, Linux는 `xdg-open "<경로>"`. 실패하면 경로를 알려주고 직접 열라고 안내한다.
4. **마무리:** 이번 복습에서 맞힌 개수, 리포트 경로, 다음에 공부할 것을 짧게 알린다.
